history:

1. verify NEXUS host integrity and hardware recovery;
2. check the hypervisor without changing host configuration;
3. inspect IA_LAB VM state and preserve its disks/snapshots;
4. inspect and start Gitea only under its existing service contract;
5. verify Gitea repository identity and remotes;
6. locate `AETHERIS_AI`, branches, tags and default branch;
7. capture HEADs, refs and a safe repository backup;
8. run `git fsck` on recovered clones where appropriate;
9. compare Gitea history with any local recovered copy;
10. reconcile the recovered source against Governance revision
    `ff1318cd8f0a9720f66029e3985d1e5854044128`;
11. only then resume G4.6 implementation placement.

Do not execute this checklist while NEXUS remains unavailable. Do not create a
new GitHub repository solely to replace unavailable historical source.
