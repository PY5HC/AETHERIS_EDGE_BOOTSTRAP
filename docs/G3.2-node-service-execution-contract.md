# G3.2 — Node Service Execution Contract

## Scope and authority

G3.2 defines the future systemd execution boundary for the AETHERIS Node
Agent. It does not install a unit, create runtime or state leaves, create an
account, grant Docker or GPU access, or mutate the platform. Configuration is
bootstrap/root authority under `/etc/aetheris`; releases are governed/root
authority under `/opt/aetheris`.

The reviewed Node Agent source authority is the private `PY5HC/AETHERIS_NODE_AGENT`
repository at revision `4cbea2ff1018a604cfa6b063545efc155e70fc5b` on `main`.
That source is a Python package named `aetheris-node-agent`, requiring Python
3.11 or newer and packaged with Hatch. It has an application factory
`aetheris_node_agent.presentation.runtime_http_app:create_runtime_app` and
optional web dependencies, but no declared console script, `__main__` entry
point, systemd definition, release artifact, or deployment manifest at this
revision.

Therefore the exact production executable and release layout are not yet
established. `ExecStart` is intentionally unresolved and this template is not
installable. A future release gate must bind the token to an absolute,
provenance-verified executable in `/opt/aetheris/releases/<release-id>` before
any unit materialization.

## Service identity and authority

The future unit uses `User=aetheris-node` and `Group=aetheris`. It has no
sudo, Docker group, supplementary groups, login shell, or home dependency.
Configuration remains read-only to the service. The service must not own or
write `/etc/aetheris`, `/etc/aetheris/node`, `/opt/aetheris`,
`/opt/aetheris/releases`, or `/opt/aetheris/current`.

`/opt/aetheris/current` remains a directory in v1. No symlink migration or
implicit fallback to another checkout, PATH, home directory, `/usr/local/bin`,
container, or alternate Python module is permitted.

## Runtime, state, and logging contract

Systemd will own these service leaves when a real release is available:

```ini
RuntimeDirectory=aetheris/aetheris-node
RuntimeDirectoryMode=0750
StateDirectory=aetheris/node/aetheris-node
StateDirectoryMode=0750
```

The existing G3.0 tmpfiles policy owns only `/run/aetheris`; no G3.2 leaf
tmpfiles entry is added. No `LogsDirectory` is used. Standard output and
standard error go to journald.

## Lifecycle and fail-closed behavior

The unit is not installed or enabled by G3.2. A missing or unresolved
executable, missing governed release, conflicting unit, or invalid rendered
contract must fail before any live mutation. No silent fallback is allowed.

The bounded restart policy is:

```ini
# [Unit]
StartLimitIntervalSec=60s
StartLimitBurst=5

# [Service]
Restart=on-failure
RestartSec=10s
```

Persistent crash loops must become visibly failed after the burst limit.

## Hardening decisions

Accepted for the future unit, subject to service smoke testing:

- `NoNewPrivileges=yes`
- `PrivateTmp=yes`
- `ProtectHome=yes`
- `ProtectKernelTunables=yes`
- `ProtectKernelModules=yes`
- `ProtectControlGroups=yes`
- `ProtectClock=yes`
- `ProtectHostname=yes`
- `RestrictSUIDSGID=yes`
- `LockPersonality=yes`
- `RestrictRealtime=yes`
- `SystemCallArchitectures=native`
- `UMask=0027`

`ProtectSystem=strict` is deferred until the real release and writable-state
requirements are tested. `MemoryDenyWriteExecute` is deferred because Python,
native extensions, JIT, and inference implementations may require executable
memory. `PrivateDevices=yes`, `DevicePolicy=`, and `DeviceAllow=` are deferred
until actual native GPU, SDR, or USB requirements are established; no device
allowlist is inferred from filenames.

## Source/runtime interface facts

The source currently requires `AETHERIS_NODE_ID` and exposes health, node, and
capabilities HTTP routes through the application factory. It also defines
optional RF and realtime executor path environment variables. No Docker or
NVIDIA service authorization is established by this source review. Signal and
standalone server behavior are not established because there is no service
runner or `__main__` entry point in the reviewed revision.

## Deferred gates

G3.3 must establish the immutable release directory, package/venv or binary
installation, dependency provenance, release manifest, executable path,
health/readiness startup behavior, shutdown behavior, and rollback policy.
Only then may a rendered unit replace `@AETHERIS_NODE_EXECSTART@`, undergo
independent review, and be installed by a separately authorized live gate.
