# G3.0 — AETHERIS Edge Node Bootstrap Contract

## Authority and scope

AETHERIS Governance defines policy; this repository materializes the node
bootstrap contract. Vendor NVIDIA files and services remain outside AETHERIS
authority. The G2.12A.1 `nvpmodel` guard stabilizes platform power-mode boot
behavior; it is not the authority for node identity.

## Identity v1

The contract keeps one file: `/etc/aetheris/node/identity.env`. It has two
classes of fields. Stable identity/profile fields are `AETHERIS_NODE_ID`,
`AETHERIS_NODE_ROLE`, `AETHERIS_NODE_CLASS`, `AETHERIS_PLATFORM`, and
`AETHERIS_MACHINE_ID`. Observed platform facts are `AETHERIS_HOSTNAME`,
`AETHERIS_ARCH`, `AETHERIS_KERNEL`, `AETHERIS_OS`, `AETHERIS_L4T_RELEASE`,
`AETHERIS_JETPACK_RELEASE`, `AETHERIS_POWER_PROFILE`, and
`AETHERIS_BOOT_PROFILE`. Observed facts are a materialized bootstrap snapshot
and `verify-node-contract.sh` revalidates them. No real machine-id is stored
in Git.

## Discovery-before-mutation

`apply-node-contract.sh` must complete all discovery, validation, template
rendering, placeholder checks, and JSON validation before its first persistent
mutation. Any failure therefore fails before group creation, installation,
tmpfiles creation, or directory changes. It performs only read-only power
querying (`/usr/sbin/nvpmodel -q`) and never changes the default target.

The supported profile is Jetson Orin Nano Super: the physical model is read
from NUL-terminated `/proc/device-tree/model`, `aarch64` is required, and the
canonical platform is `jetson-orin-nano-super`. OS, L4T, CUDA, cuDNN, TensorRT,
VPI, JetPack, Docker, NVIDIA Container Toolkit/CDI, power profile, and boot
profile are discovered from the running node. `multi-user.target` maps to
`headless-conservative`; other targets are unsupported. A platform override is
accepted only when it matches detected hardware.

## Verification responsibilities

The verifier is read-only. It checks directories, ownership, modes, the
`aetheris` group, identity/capability file metadata, exact identity key set,
duplicates, unknown/missing/empty/placeholders, and all observed facts against
current discovery. Python validates capability semantics, including schema,
identity, platform, discovered accelerator versions, NVIDIA CDI and Docker
flags, and the not-installed states for node-agent, sky, rf, and local-ai. It
also checks Docker service availability, `nvidia-ctk`, CDI NVIDIA devices, and
the exact tmpfiles line:

```text
d /run/aetheris 0755 root aetheris -
```

## `/opt/aetheris/current` v1

`/opt/aetheris/current` is currently a bootstrap filesystem directory. It is
not canonical release identity and is not a release symlink. Future governed
release management may migrate it to:

```text
/opt/aetheris/current -> /opt/aetheris/releases/<release>
```

That migration is intentionally not implemented in G3.0 v1.
