# G2.12A.1 — nvpmodel headless boot idempotence

## Problem

On the Jetson Orin Nano Super reference node, the NVIDIA
`nvpmodel.service` intermittently exits with status 234 during boot.

The vendor service invokes:

`/usr/sbin/nvpmodel -f /etc/nvpmodel.conf`

When the persisted mode is already active, some boots enter an
interactive reboot-confirmation path. Under systemd there is no
interactive answer, producing `bad input` and leaving the unit failed.

Observed functional state remains MAXN_SUPER / mode 2.

## Constraint

Do not modify NVIDIA package-owned files.

Do not use `--force`, because that option may automatically reboot the
node when nvpmodel determines that a reboot is required.

## Remediation

Install a systemd `ExecCondition` drop-in.

The condition compares:

- the current numeric mode reported by `nvpmodel -q`;
- the persisted numeric mode in `/var/lib/nvpmodel/status`.

If both valid values are equal, the condition exits 1. systemd skips the
vendor ExecStart without marking the service failed.

If the values differ, or if state cannot be determined reliably, the
condition exits 0 and preserves the original NVIDIA behavior.

## Authority

This is an operational platform stabilization layer.

It does not replace NVIDIA power-mode authority and does not alter the
vendor nvpmodel service, binary, configuration, or persisted mode.
