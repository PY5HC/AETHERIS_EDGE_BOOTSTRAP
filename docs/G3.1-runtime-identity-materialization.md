# G3.1C.1 — Runtime Identity Materialization

## Scope

This gate defines the repository-side materialization contract for the
`aetheris-node` service identity. The apply script is intentionally not run by
this gate and no account, group, unit, runtime leaf, or state leaf is created
here.

## Canonical account

```text
name: aetheris-node
primary group: aetheris
shell: /usr/sbin/nologin
home: /nonexistent (no home directory)
password: locked/unusable
supplementary groups: none
sudo: none
Docker group: none
```

The materializer uses an explicitly bounded system-account command and does
not select a fixed UID. The operating system allocates a valid system UID.
An existing account is never silently repaired: an exact account is a
semantic no-op, while any mismatch fails closed.

## Authority and preconditions

`/etc/aetheris` and `/etc/aetheris/node` remain root/bootstrap configuration
authority. `/opt/aetheris`, `/opt/aetheris/releases`, and
`/opt/aetheris/current` remain root/governed release authority. The service
does not own or write those parents.

Before the first persistent mutation, the materializer validates repository
authority, the `aetheris` group, NSS collisions, account tools and policy,
all G3.0 parent metadata, absence of service-owned leaves, absence of the
service unit, and absence of Docker authorization. A restricted path is
classified as `PERMISSION_DENIED`, never as absent. Only then may `useradd`
be invoked.

The optional `AETHERIS_EXPECTED_BRANCH` and `AETHERIS_EXPECTED_HEAD`
environment variables allow a governed caller to pin repository execution to
known authority. They are not implicit machine identity.

## Idempotence

- Missing account plus valid preconditions: create the exact account.
- Existing exact account: do not call `usermod`; return a semantic no-op.
- Existing account with any different UID, primary group, shell, home,
  supplementary group set, or password state: fail closed.

## Verification

`verify-node-runtime-identity.sh` is read-only. It verifies the materialized
account, NSS source, system UID policy, primary and supplementary groups,
shell, absent home directory, locked password, sudo/Docker boundaries,
pre-existing unit and service leaves, and unchanged G3.0 parent authority.
Password state is `LOCKED=PASS`, `USABLE=FAIL`, and inaccessible or unknown
inspection is `NOT_VERIFIED`/blocked. Permission denial is never interpreted
as absence.

## Deliberate non-scope

This gate does not install a systemd unit, create runtime or state leaves,
install Node Agent, grant Docker access, add GPU policy, change NVIDIA files,
change power mode, or alter packages. `/run/aetheris/aetheris-node` and
`/var/lib/aetheris/node/aetheris-node` remain future systemd-owned leaves.
