# G4.2 — Reproducible llama.cpp Experimental Build

G4.2 establishes `ggml-org/llama.cpp` as an experimental backend candidate;
it does not make llama.cpp AETHERIS authority and does not install a runtime,
model, service, or system package.

## Pinned source and host

- URL: `https://github.com/ggml-org/llama.cpp.git`
- commit: `6a1a922d269908a29cbd4b49c27e6a8e7fd10fae`
- commit date: `2026-09-05T12:19:47+02:00`
- license: MIT
- target: native `aarch64` Jetson Orin Nano Super
- build system: CMake; backend option `GGML_CUDA=ON`; observed native CUDA
  architecture `87-real`, selected explicitly as `CMAKE_CUDA_ARCHITECTURES=87`
- build type: `Release`; `GGML_NATIVE=OFF`
- runtime linkage: `CMAKE_INSTALL_RPATH=$ORIGIN` with
  `CMAKE_BUILD_WITH_INSTALL_RPATH=ON`; no build-tree RUNPATH
- compile paths are normalized with a source prefix map, so runtime-critical
  ELF strings do not retain temporary checkout paths.
- optional UI assets: `LLAMA_BUILD_UI=OFF`, `LLAMA_USE_PREBUILT_UI=OFF`
  (no unpinned network asset)
- unified app target is disabled because this pinned revision has an
  upstream `build-info.h` include defect; the candidate uses the validated
  `llama-cli` and `llama-server` targets.

The build must use an exact detached source revision, record the compiler,
CMake and CUDA toolchain, and use a clean non-authoritative staging root.
The builder rejects live AETHERIS output locations and never installs
packages or services.

## Artifact and lifecycle contract

The generated manifest records source URL/commit/date/license, target
architecture, toolchain, CUDA version, flags, relative artifact paths and
SHA-256 values. No build directory, `/tmp` path, home path, or ambient PATH
may become runtime authority. A later release gate must independently verify
the manifest before any installation.

The staged runtime is copied to a second temporary root and probed there
after the original build root is unavailable. Removal is limited to the
isolated staging root and must not touch NVIDIA, system Python, Node Agent r5,
G3 files, live services, or Governance.

Any source, toolchain, hash, architecture, build, linkage, or relocation
mismatch fails closed. No model is acquired in G4.2; GPU execution proof and
the first model are separate later gates.
