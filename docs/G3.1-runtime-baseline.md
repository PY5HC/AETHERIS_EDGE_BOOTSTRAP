# G3.1 — AETHERIS Runtime Baseline

## Scope

G3.1 establishes the runtime identity and service-baseline design only. It
does not create accounts, install services, install Node Agent, grant Docker
access, add GPU device policy, or mutate system state.

## Service identity

The future service identity is:

```ini
User=aetheris-node
Group=aetheris
```
The account is intended to be a system account with no interactive login, no
password (no password authentication), no home directory unless later justified, no sudo authorization, and
no Docker group membership. It must not own canonical configuration or release
content.

## Filesystem authority

- `CONFIG_AUTHORITY`: root / G3 bootstrap (`/etc/aetheris`, `/etc/aetheris/node`)
- `RELEASE_AUTHORITY`: root / governed release process (`/opt/aetheris`,
  `/opt/aetheris/releases`, `/opt/aetheris/current`)
- `SERVICE_STATE`: `/var/lib/aetheris/node/aetheris-node`
- `SERVICE_RUNTIME`: `/run/aetheris/aetheris-node`
- `LOGGING`: journald via service stdout/stderr

G3.1 does not create a filesystem log directory. The service receives no write
access to parent configuration or release directories.

## Directory lifecycle

The existing G3.0 tmpfiles contract owns only the bootstrap runtime parent
`/run/aetheris`. G3.1 deliberately adds no duplicate tmpfiles entry. The future
systemd unit will own the service runtime leaf with:

```text
/run/aetheris/aetheris-node
```

Persistent service state will be owned by the future unit at:

```text
/var/lib/aetheris/node/aetheris-node
```

Neither service-owned leaf is materialized by this repository baseline.

## Release model

`/opt/aetheris/current` remains a directory in G3.1. Symlink migration to a
governed release target is deferred to a later release-management gate. Node
Agent unit installation is also deferred until a governed release exists. No
implicit alternate release selection is allowed.

## Future bounded restart policy

The future service contract will use:

```ini
Restart=on-failure
RestartSec=10s
StartLimitIntervalSec=60s
StartLimitBurst=5
```

This permits transient recovery while stopping persistent crash loops and
leaving the unit visibly failed.

## Systemd and GPU boundary

The systemd unit implementation is deferred. No unit, executable path, Docker socket authorization, or GPU device policy is
introduced by G3.1. Native CUDA device policy remains deferred until an actual
Node Agent workload is tested.

## Responsibility boundary

- Bootstrap owns host identity, parent directories, permissions, and capability
  contract.
- The future Node Agent owns lifecycle and service-specific state.
- Workloads own application execution and any separately governed container/GPU
  policy.

G3.1 does not install Node Agent or create its release tree.
