# G3.6 — Node service materialization contract

G3.6 resolves the reviewed Node Agent runner to a release-specific absolute
path. `scripts/render-node-service-contract.sh` accepts only a validated
manifest and an executable under `/opt/aetheris/releases/<release-id>/`; it
renders a disposable unit file and never installs, enables, starts, or
reloads systemd. The release manifest remains the source of release and
Governance provenance.

The future unit runs `aetheris-node:aetheris`, reads the root-owned identity
file, binds only to `127.0.0.1:8000`, writes only systemd-managed nested
runtime/state leaves, and logs to journald. It has no Docker, GPU, sudo,
supplementary-group, or home authority. `ProtectSystem=strict`,
`MemoryDenyWriteExecute`, device policy, and `PrivateDevices` remain deferred
until a real workload validates them.

The renderer rejects unresolved tokens, PATH/home/checkout fallbacks, missing
executables, mismatched release IDs, and output paths under live authorities.
Installation and activation require a separate reviewed live gate. The
G3.0/G3.1 `/opt/aetheris/current` directory is not migrated here.

The reviewed first-release path is `scripts/materialize-node-agent-release.sh`.
It derives `RELEASE_ID` from the staged manifest rather than operator input,
checks the wheel and dependency-lock hashes plus source and Governance
provenance, rejects an existing release or conflicting unit, and defaults to
validation-only. `AETHERIS_LIVE_APPLY=YES` is the explicit live gate; it is not
executed by repository validation.

The failed `20260904-node-agent-r1` release is retained as immutable forensic
evidence and is never overwritten. Its generated shebang referenced a deleted
build-temporary virtualenv. The corrected release is
`20260905-node-agent-r2`: a clean `release-venv`, source collected with
`git archive`, and a relocatable `venv/bin/aetheris-node-agent` launcher that
resolves its sibling interpreter. Build/test caches are excluded.

The corrected unit uses valid `ConditionPathExists=` and
`[Install] WantedBy=multi-user.target`; the previous unsupported condition and
static boot policy are not part of the corrected contract.
